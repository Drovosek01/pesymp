Утилита для поиска функций/переменных/символов в PE-бинарниках на Windows и вывода их адресов (RVA, VA, смещение в файле), а также для оперативного патчинга найденных участков.

---

## Предисловие

Данная утилита создана на основе идеи утилиты symp ([Antibioticss/symp](https://github.com/Antibioticss/symp) и [Drovosek01/symp](https://github.com/Drovosek01/symp)).

В основном я создавал эту утилиту для того, чтобы получать адреса функций `WinVerifyTrust` в exe, dll и других PE-файлах без ожидания, пока файл проанализируется в IDA Pro (потому что это ощутимо долго).

Утилита сканирует таблицы экспорта, импорта, таблицы символов COFF, а также сканнирует инструкции вызова/перехода (thunks и thunk-calls) в исполняемых секциях.

Разумеется утилита создана руководствуясь помощью нейронных сетей.

## Сборка

Утилита написана на C# и не требует сторонних зависимостей. Для сборки достаточно стандартного компилятора C# (`csc`), входящего в состав .NET Framework или Visual Studio / Build Tools.

### Ручная сборка через компилятор C# (csc)

Если .Net SDK не установлены:
```powershell
& "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe" /nologo /optimize+ /out:pesymp.exe Program.cs
```
Если .Net SDK установлены и csc.exe добавлен в PATH:
```cmd
csc /nologo /optimize+ /out:pesymp.exe Program.cs
```

### Автоматическая сборка скриптом

Просто выполните `build.ps1` в терминале:
```powershell
.\build.ps1
```

## Использование

Общий синтаксис команды:

```cmd
pesymp [options] <symbol> <path to file>
```

Или для прямого патчинга по байтовому смещению:

```cmd
pesymp -x <hex bytes> -- <file offset> <path to file>
```

## Аргументы использования

### Опции поиска
* `-r` — рассматривать паттерн как регулярное выражение.
* `-c` — учет регистра (по умолчанию поиск регистронезависимый).
* `-l` — вывести список всех символов (паттерн не требуется).
* `-t <table>` — искать в конкретной таблице/источнике. Допустимые значения: `export`, `import`, `coff`, `thunk`, `thunk-call`, `all` (по умолчанию `all`). Можно указывать несколько раз.

### Опции патчинга
* `-x, --hex <data>` — пропатчить найденные смещения (или указанный адрес) hex-данными (регистр не важен, допускаются пробелы, например: `-x "90 90 90"` или `-x 31c0c3`).
* `--` — разделитель между флагами опций и позиционными аргументами (паттерном/адресом и файлами).

### Опции вывода
* `-q, --quiet` — тихий режим (выводит только адреса).
* `--addr <type>` — тип адреса для тихого режима: `rva`, `va`, `offset` (по умолчанию `offset`).
* `-n, --names-only` — выводить только имена символов (по одному на строку).
* `--no-header` — не выводить заголовки таблиц.
* `-f <format>` — формат вывода результатов: `table` (по умолчанию), `raw`, `csv`, `json`.

## Примеры использование

Для экспериментов можно взять, например, [пару файлов](https://mega.nz/file/ciA3QK5Q#PYl7Nrech5uyloguN7DJU_ZQlNQSnUD7UUaCfdMeA4M) из установленного Adobe Premiere Pro 2026 v26.3.2

Базовый поиск символа/функции `CreateFile` в `kernel32.dll`:
```cmd
pesymp.exe CreateFile C:\Windows\System32\kernel32.dll
```

Поиск всех символов с использованием регулярных выражений, содержащих в названии паттерн `Api...Buffer`:
```cmd
pesymp.exe -r "Api.*Buffer" app.exe other.dll
```

Вывод всех доступных символов без применения фильтра:
```cmd
pesymp.exe -l app.exe
```

Поиск `WinVerifyTrust` через таблицы переходов (thunk) и вывести только его Virtual Address (VA):
```cmd
pesymp.exe -t thunk -q --addr va WinVerifyTrust app.exe
```

Экспорт результатов в формате JSON:
```cmd
pesymp.exe -t export -t import -f json -l app.exe > output.json
```

Патчинг по найденным символам - Найти функцию `CreateFile` в `kernel32.dll` и сразу пропатчить её смещение байтами `NOP` (`909090`):
```cmd
pesymp.exe CreateFile kernel32.dll -x 909090
```

Пропатчить файл по указанному файловому смещению `0x10002a704` байтами `NOP`:
```cmd
pesymp.exe -x 909090 -- 0x10002a704 file.exe
```
